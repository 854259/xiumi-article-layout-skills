# 推文撰写与秀米排版 Skills

从素材整理、栏目撰写、审阅改稿，到秀米逐段排版、配图配色、横向滑动、保存核验与经验迭代的一套中文工作方法。

适用于公众号人物访谈、活动总结、节日合辑、预告招募和政策服务文章。平台操作以当前可见界面和所用工具文档为准；其他编辑平台可以复用适用的文字、文图核对及验证原则。

## 入口

- [SKILL.md](SKILL.md)：任务分流和完整工作流程。
- [撰写与审阅](references/writing-and-review.md)：五类体裁、语言风格、事实核对和定向改稿。
- [秀米操作](references/ui-workflow.md)：选模板、另存、逐段编辑、真实缩进、加滑动页、逐页换图与双向核验。
- [配色与恢复](references/color-and-recovery.md)：连接恢复、组件层级、纯色与渐变、标题阴影、保存及阅读预览案例。
- [经验迭代](references/learning-loop.md)：记录新问题、验证解法、合并重复经验和公开贡献。

## 使用

将仓库内容放入个人 skills 目录下的 `xiumi-article-layout` 文件夹，确保 `SKILL.md`、`agents/` 和 `references/` 层级保持完整；已有同名技能先检查差异并保存当前版本。安装位置采用所用AI工具的实际配置。

支持显式调用 `$xiumi-article-layout`，并在支持技能自动发现的环境中保留自然语言调用。示例：

- “根据采访素材起草一篇人物访谈推文，沿用本栏目框架。”
- “审阅这篇活动总结，先看事实和流程，再精简文字。”
- “继续排这篇推文，把滑动加到8页，按给定顺序替换照片。”
- “只调整装饰配色，保留文字、图片、顺序和其他格式。”

默认格式参考：正文15px、字距1px、行距1.8倍、真实首行缩进、左右20px。当前用户的具体要求优先；特殊卡片按容器结构调整。

## 经验回馈

每位使用者独立选择是否反馈。在有值得分享的经验且尚未表态时，AI会专门询问：是否愿意把使用中遇到的困难、修复步骤和验证结果脱敏后传回本仓库。**明确愿意才提交；不愿意就跳过，当前任务照常完成。** 未回答、安装或克隆技能都不视为同意，选择只保存在使用者本地，范围不变时继续沿用。

愿意反馈的使用者可通过 [Issues](https://github.com/854259/xiumi-article-layout-skills/issues) 分享“遇到什么问题、如何解决、怎样验证”，并通过 PR 更新对应参考；有直接维护权限且已授权同步的账号可使用附带同步工具。详见 [CONTRIBUTING.md](CONTRIBUTING.md)。

所有协作规则公开可读。使用者保有对自己的资料、账号和提交动作的选择权；AI执行外部提交时依据当前用户授权。素材原文、人物照片、私聊、账号信息与临时预览凭证由使用者本地保管，公开案例采用角色名称与中性操作场景，保留方法和必要参数。

## 同步更新

技能提供 [scripts/sync_skill.py](scripts/sync_skill.py)，在任务收尾合并已验证经验后执行“源码检查 → 安装版同步 → 已授权仓库同步 → 回读验证”。默认只检查；`--apply`同步本地安装；`--push`还会核对远程基线并普通推送。使用Python 3标准库和Git，具体本地配置及冲突处理见[可执行同步](references/learning-loop.md#可执行同步)。

同步配置、文件哈希基线和反馈选择留在本机；公开内容使用固定清单。已有本地或远程改动发生冲突时先报告和合并，保留各自内容。工具不在后台自动收集经历，也不因使用技能而自动上传。

收藏模板、院标和署名随账号与任务变化，先查看当前用户实际收藏及需求，再选取适用组件。其他使用者可以复用操作方法，同时采用自己的素材和样式。
