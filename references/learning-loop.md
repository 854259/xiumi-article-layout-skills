# 经验迭代与共同维护

适用：本技能执行中出现新困难、新控件行为、用户新教法或新的有效解法。

## 本地闭环

1. **先接续，再定位。** 读当前任务记录和相关案例，确认文章、版本、已保存位置和当前问题。优先复用同一环境中已有的成功方式。
2. **记录最小事实。** 写下可观察现象、当时的焦点/选区/容器层级、使用的控件和反馈。原因尚待验证时使用“可能原因”或“待验证”。
3. **一次验证一个判断。** 对最小范围尝试修正，读回状态，再决定下一步；修正前保留必要恢复点。反复出现相同反馈时，调整诊断信息和假设。
4. **验证真实结果。** 文字用全文或段落回读，样式用实际值和视觉检查，滑动用逐页身份检查与双向操作，保存用重新加载。记录验证的环境和范围。
5. **写进已有参考。** 相同问题补充原案例，新问题增加简洁条目。优先修改对应操作段落；较长案例单列参考并从入口链接。已验证解法与待验证建议分别标记。
6. **保留可迁移条件。** 保存控件名称、选择层级、判断依据和结果。公开案例使用角色名称和中性操作场景；具体人员、项目、活动、组织、栏目及群体标识留在原始任务记录中。坐标、标签ID、数量和色值按当前页面重新确认。
7. **同步与检查。** 在当前用户已授权维护技能的范围内，更新技能源码、安装副本和现有任务记录；检查链接、元数据、适用范围及文件一致性。历史版本按项目Git规则留存，清理本轮临时材料。

## 案例最小格式

```text
标题 / 日期：
来源类型：用户明确教法 / 实际操作验证 / 范例归纳
适用场景与环境：
观察到的现象：
原因或待验证判断：
有效步骤：
结果与验证证据：
适用边界：
下次可提前做的检查：
```

失败尝试只保留对下一次选择有帮助的结论。工作流设计建议标记“流程建议”，实际成功操作标记“已验证”。由单次案例得出的步骤，随下一次使用再次检查页面和条件。

## 公开贡献

仓库的 README、技能和贡献指南明示经验回馈流程，使用者自愿参与。建议在遇到有复用价值的问题后，提供“现象—步骤—验证—适用范围”，通过 Issue 讨论，再通过 PR 更新对应参考。

- 发布内容以通用方法和最小可复现实例为主；人物素材、原稿、私人路径、账户信息、临时预览凭证及私聊保留在各自本地资料中。
- 发起 Issue、PR、提交或推送前，按当前用户对具体仓库和内容的授权执行；拉取、安装与日常使用仅开展已授权的任务。
- 仓库经验经维护者检查证据、适用条件与表达后合并。读者根据自己的当前需求决定采用哪些方法。
- 本技能通过可见文字指导任务后的复盘与维护；本地写入、远程发布和定时执行分别由对应环境及用户授权驱动。

新增案例同时检查三件事：是否复现了问题，解法是否验证了实际结果，通用规则是否保持了原任务范围。

## 已验证案例：新建仓库的上传权限

- **现象与范围：** 用户已授权公开通用技能；网页成功创建公开仓库，连接器读取仓库正常，写入接口返回403及 `Resource not accessible by integration`。
- **判断：** 当前连接器的写入权限与已登录用户的仓库权限分别核对。该错误属于此连接路径的能力限制；安全审批拒绝或用户撤回授权则按其具体要求处理。
- **有效步骤：** 先确认仓库身份、公开范围与文件清单，再使用本机已配置的Git凭据管理器，单独建立本次公开文件的提交并正常推送。凭据由Git管理器处理；进程采用非交互模式，遇到认证缺口时按当前工具流程恢复。
- **验证：** 推送后回读远程分支、公开属性、许可证及完整文件树，逐文件比较Git对象哈希与大小。公开包与私人项目版本分别留存。
- **收尾与改进：** 复查远程内容后清理本轮临时发布目录。以后先核对连接器对目标仓库的写入能力，并将上传文件限制在明确的技能清单内。
